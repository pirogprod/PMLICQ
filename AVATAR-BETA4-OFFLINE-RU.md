# PMLICQ V9 — Avatar Beta 4 (на базе Crash Fix 3)

Основа: `PMLICQ_V9_AVATAR_BETA3_CONTACT_API_CRASH_FIX3_SOURCE.zip`, который уже работал у пользователя с Miranda NG 0.96.7 #28846 x64, UIN и AIM SN. Все четыре ветки получили одинаковые исправления обнаружения аватаров. Версия обычной 0.96.7 повышена с 0.1.0.3 до 0.1.0.4, остальные номера оставлены прежними.

## Изменения

* BUDDY ARRIVED/DEPARTED (03/0B, 03/0C) могут содержать несколько последовательных USERINFO. Раньше в обработчик передавался весь пакет, но извлекался только первый контакт. Теперь при строго корректной структуре записи разделяются и каждая передаётся в существующий обработчик. Одиночные сообщения, устаревшие name-only DEPART и нестандартные/усечённые пакеты сохраняют прежний путь. Не создаются новые контакты из метаданных аватаров.
* Сохранены флаги BUDDY RIGHTS `0x0007`, запрос LOCATE 02/15 после входа и при добавлении, приоритет новых контактов, восстановление известного хеша из кэша. Если офлайн-контакт по-прежнему не имеет ни известного, ни кэшированного хеша, через 5 секунд (или позже в большой очереди) допускается один дополнительный запрос. Для UIN — старый LOCATE 02/05 (тип 2, короткая информация), для AIM — повтор 02/15. Это совместимый по формату, но не гарантированный по серверной поддержке резервный путь. Повтор отменяется при получении хеша, переходе контакта онлайн или удалении контакта. Нет бесконечного опроса; максимум 4 запроса в одном секундном интервале суммарно, включая старую очередь. При новой сессии состояние очищается. При добавлении принудительная очередь сохраняется.
* LOCATE 02/06 и 02/01 теперь логируются с количеством найденных ID аватаров или кодом серверной ошибки. Ответы на запросы метаданных по-прежнему не меняют статус, X-status или профиль.

Не изменены: `proto.cpp` (включая переходник ABI Crash Fix 3, AVS, собственный аватар и добавление контакта), `oscar.cpp`, BART 10/06 и 10/07, запись картинок и ContactPhoto/File, уведомление ACKTYPE_AVATAR, BART worker, SSI-публикация собственного аватара, AIM/UIN, ARS/OFT2, X-status, Fingerprint, авторизация. Код существующих обработчиков одиночного присутствия сохранён побайтно. PMLMRIM не изменялся. Diff к рабочей версии: `AVATAR-BETA4-OFFLINE.patch`.

## Сборка и проверка на сервере

1. Сохранить рабочую DLL 0.1.0.3 и резервную копию профиля. Для #28846 x64 заменить каталог `plugins/KICQ` на `normal/0.96.7/KICQ` из данного архива. Clean -> Rebuild, Release x64, тот же SDK, на котором собирался Crash Fix 3. Установить DLL 0.1.0.4 при закрытой Miranda. Не менять контактный ABI/флаги сборки.
2. На копии профиля проверить холодное получение аватара офлайн-контакта (который ещё не был онлайн с этим профилем, но на сервере действительно имеет картинку). Дождаться первичной очереди и дополнительного запроса. Отдельно проверить уже имеющийся кэш, онлайн-контакт, смену аватара онлайн, добавление нового онлайн/офлайн UIN и AIM SN, собственный аватар. Не удалять рабочий кэш и контакты из основного профиля ради теста.
3. Если неизвестная офлайн-аватарка не получена, записать Netlib log получателя с момента входа до завершения очереди. Искомые строки:
   * `BART: requested avatar metadata` / `BART: offline metadata retry`
   * `BART: LOCATE 02/06 for ... icon IDs=...` / `BART: LOCATE error 02/01`
   * `BART: received ... batched BUDDY records`
   * `BART: queued image request` / `BART: cached and announced` / `BART: image request failed`

Если оба запроса возвращают ошибку, нет ни одного ID аватара в ответах и нет уведомлений 03/0B или 03/0C с TLV 001D, неизвестный хеш клиенту неоткуда взять. Нельзя гарантировать холодную загрузку офлайн без поддержки сервера. Запрос BART 10/06 требует идентификатор аватара; не нужно подставлять фиктивные хеши или обращаться к недокументированным API. Приложенный ранее серверный пример `bart.rs` также требует действительный хеш. Его не изменяли. При такой диагностике понадобится серверный лог/код формирования USERINFO и presence, а не очередная переработка исправного скачивания BART. Перед отправкой логов удалить пароли, cookies и токены; не прикладывать профиль.
