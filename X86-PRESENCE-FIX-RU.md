# PMLICQ V9 — Avatar Beta 4 / x86 Presence Fix

База: PMLICQ_V9_AVATAR_BETA4_OFFLINE_CRASH_FIX3_SOURCE.zip. Не меняется версия DLL (в том числе x64); новая x86-сборка узнаётся по строкам `PRESENCE x86:` в Netlib. PMLMRIM не изменялся.

## Изменения

Во всех четырёх каталогах правки только в `src/server.cpp` и `src/proto.h`, под `#if defined(_WIN32) && !defined(_WIN64)`. Для x64 содержимое исходников после исключения этих блоков совпадает с исходной Beta 4. Остальные файлы исходной поставки не изменены.

В исходной последовательности 03/04 (BuddyAddBuddies), 01/02 (ClientOnline), 13/07 (FeedbagUse) серверный SSI активировался после ClientOnline. Open OSCAR Server выполняет первоначальную рассылку видимости для большинства клиентов в ClientOnline; позднее FeedbagUse запускает её только для ICQBasic. Также OOS не разрешает клиентскую подписку AIM -> числовой ICQ UIN (03/04), этот случай должен работать через SSI с авторизацией. Это подтверждённые особенности серверной реализации, но без лога x86 точная причина пользовательского сбоя не доказана.

На x86:
- 13/07 перед 01/02, ранняя подписка 03/04 для совместимых контактов сохранена.
- Через 4 секунды после входа однократно повторяется 03/04 для ещё не получивших онлайн-статус авторизованных SSI-контактов, кроме AIM -> UIN. Не отправляются запросы для отсутствующих и временных контактов. Не обходятся ограничения сервера и приватности; статусы не выдумываются из LOCATE/BART.
- Подписки отправляются пакетами до 50 имён/3500 байт без удержания блокировки списка во время отправки. Таймер сбрасывается при новом входе; повтор не выполняется в офлайне.
- Диагностика `PRESENCE x86:` сообщает тип аккаунта, числа подписок и ожидающих авторизации/SSI-only, первые события прихода ICQ/AIM и отсутствующие записи, отклонение сервером 03/0A. Для AIM статус обновляется только при изменении значения; обработка офлайн-BART остаётся прежней.

Не изменены: код BART/аватаров (включая Beta 4), поиск/создание контактов, авторизация, файлы, X-status, Fingerprint, Crash Fix 3. Оригинальная ветка x64 после препроцессинга прежняя. Неподтверждённые авторизации и скрытые сервером пользователи могут по-прежнему показываться офлайн.

## Сборка и проверка

Для обычной Miranda используйте `normal/0.96.7/KICQ` или `normal/0.96.8/KICQ` в соответствующем дереве SDK. Для Windows XP — отдельный `windows-xp-x86` и прежний toolset. Release | Win32, Clean -> Rebuild. Не заменяйте уже рабочую x64 DLL. Сохраните резервные копии профиля и старой x86 DLL.

Проверьте отдельные входы UIN и AIM SN, существующих онлайн и офлайн контактов обоих типов, выход/вход собеседника, повторное подключение, авторизацию. Убедитесь, что `PRESENCE x86: SSI activated before ClientOnline` присутствует в Netlib. Если дефект остался, нужен x86 Netlib log от подключения до 10–15 секунд после входа, версия ядра и тип аккаунта. Удалите секреты перед отправкой. В частности интересны 13/06, 13/07, 01/02, 03/04, 03/0B, 03/0C, 03/0A и строки PRESENCE x86.

## Проверки в среде Linux

- tests/test_x86_presence.py: 4 запуска реальных извлечённых методов с заглушками Miranda/BOS, включая порядок пакетов, AIM/ICQ фильтрацию, авторизацию, 130 контактов, отсутствие отправки под блокировкой, одноразовый повтор и отсутствие повтора офлайн.
- tests/test_avatar_offline_beta4_queue.py: 4 запуска.
- tests/identity_test.cpp и tests/avatar_offline_beta4_test.cpp: по 4 запуска.
- tests/test_contact_api.py: 8 запусков.
- Сравнение всех файлов с исходным ZIP: изменены только 8 файлов исходников; после выбора x64 старый текст этих файлов совпадает побайтно.

Все 24 автономных запуска прошли. Это тесты на хосте Linux x64 с моделированием x86-ветки, не реальная Win32-компиляция: в среде нет MSVC/Windows SDK и 32-битного C++ sysroot. Исправление на живом OOS и Miranda x86 пока не подтверждено.
