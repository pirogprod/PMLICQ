# PMLICQ 0.1.0.2 — повторный crash fix для 0.96.7 #28846

Оба отчёта 25.11.2026 (20:38:31 и 20:46:09) содержат одинаковый стек: `PMLICQ + 0x1F5C5 → db_add_contact → Proto_IsProtocolLoaded → List_Find → List_GetIndex → mir_app`. Адрес чтения FFFFFFFFFFFFFFFF. DLL в новом отчёте собрана в 20:44:38, но смещения кадров остались прежними. Это сильный признак того, что компилируется тот же старый путь; без DLL/PDB и журнала сборки подтвердить причину нельзя.

В официальном SDK первоначального v0.96.7 `db_add_contact(void)`, а в ревизии 495fea6 (установленный #28846) `db_add_contact(const char *szModule, int flags = 0)` и `DBAC_NOTINLIST` определён как макрос. Экспорт функции имеет C linkage, поэтому неверная сигнатура может не приводить к ошибке линковки. См. https://github.com/miranda-ng/miranda-ng/blob/495fea6/include/m_database.h и https://github.com/miranda-ng/miranda-ng/blob/495fea6/src/mir_core/src/db.cpp.

Первый фикс выбирал API по заголовку SDK, но не запрещал сборку со старым SDK. Теперь в normal/0.96.7/KICQ/src/proto.cpp и CMakeLists.txt старый путь запрещён по умолчанию. Для нового API остаётся прямой типизированный вызов с именем аккаунта и флагами. Никаких reinterpret_cast, ручных объявлений API или подмены библиотек ядра. Добавлен вывод MSVC о выбранном ABI и версия DLL повышена до 0.1.0.2.

## Сборка для #28846 x64

1. В официальном репозитории Miranda NG выполните `git fetch origin`, затем `git worktree add --detach ../miranda-28846 495fea6`. Это даёт отдельное чистое дерево, не затирая старую сборку. В новом дереве проверьте `git rev-parse --short HEAD` (должно начинаться с 495fea6) и `git grep -n DBAC_NOTINLIST -- include/m_database.h` (определение должно существовать).
2. Скопируйте **normal/0.96.7/KICQ** из этого ZIP в **plugins/KICQ** нового дерева. Подключите проект штатным способом. Перегенерируйте решение с библиотеками и заголовками именно этой ревизии. При использовании CMake оставьте `PMLICQ_ALLOW_LEGACY_CONTACT_API=OFF`.
3. В Visual Studio выберите Release | x64, Clean и Rebuild. В выводе компилятора при компиляции proto.cpp должна присутствовать строка `PMLICQ contact ABI: new (db_add_contact(module, flags))`. Если видите `PMLICQ_CONTACT_ABI_MISMATCH`, проверьте SDK и Include Directories; не отключайте защиту и не определяйте DBAC_NOTINLIST вручную. При необходимости включите C/C++ → Advanced → Show Includes (/showIncludes) и проверьте путь к m_database.h.
4. Закройте Miranda полностью, сделайте резервную копию DLL и профиля, установите новую DLL. Проверьте в свойствах файла, что это 0.1.0.2. Сохраните PDB из той же сборки. Тестируйте сначала на копии профиля.
5. Если вновь произойдёт вылет с 0.1.0.2, приложите crash report, точный DLL + соответствующий PDB (без профиля) и строку из журнала компиляции о выбранном ABI. Это позволит локализовать реальный вызов, не угадывая по версии.

Для намеренной сборки под старый релиз v0.96.7 можно явно включить `-DPMLICQ_ALLOW_LEGACY_CONTACT_API=ON` в CMake или добавить одноимённый препроцессорный макрос в MSVC. Такой DLL нельзя использовать с #28846. XP и обе 0.96.8 ветки сохранены без изменений. PMLMRIM не менялся. Сетевые функции, аватары, авторизация, AIM и передача файлов не менялись.
