# PMLICQ 0.1.0.3 — исправление C1189 и переходник API контактов

Для обычной ветки 0.96.7. Основа: предыдущий Crash Fix 2, все сетевые функции и остальные три ветки сохранены. PMLMRIM не изменялся.

## Причина

В v0.96.7 `db_add_contact(void)`, а в ревизии 495fea6 (`#28846`) `db_add_contact(const char *szModule, int flags = 0)`. В обоих случаях экспорт имеет то же имя; старый вызов в новом ядре приводит к чтению мусора как адреса имени протокола. В Fix 2 добавлена блокировка старого SDK, поэтому компилятор показал C1189, а не создал DLL.

В Fix 3 убрана блокировка компиляции. При современном SDK используется обычный типизированный вызов. При старых заголовках проверяется фактическая версия mir_app через Miranda_GetFileVersion; только для 0.96.7.28846 берётся именованный экспорт `db_add_contact` из уже загруженного `mir_core.mir` через GetProcAddress и вызывается с `m_szModuleName` и флагом 0x0001 для временного контакта. Экспорт и значение флага проверены по официальному исходному коду этой ревизии. Никакой замены файлов ядра, ручного изменения SDK или подмены глобальных макросов. Если экспорт не найден либо версия неизвестна, по умолчанию создание нового контакта безопасно возвращает 0 с записью в Netlib log; старый вызов автоматически не применяется.

Для намеренной сборки под старый runtime с точно соответствующим старым SDK сохранена явная опция PMLICQ_ALLOW_LEGACY_CONTACT_API (по умолчанию OFF), но для #28846 она не отменяет переходник. Не включайте её для неизвестного или нового runtime. Переходник рассчитан на конкретный известный билд; не является универсальной ABI-совместимостью всех API Miranda. По возможности всё равно используйте SDK точной ревизии установленного ядра.

Дополнительно исправлены четыре предупреждения со скриншота: сравнения длины с remaining() в server.cpp (C4018, два места), затенение info в диагностике OFT2 (C4456), неиспользуемый UIN в HandleTyping (C4189). Поведение парсеров и передачи файлов не менялось.

## Сборка под установленную 0.96.7 #28846 x64

1. Замените каталог plugins/KICQ на normal/0.96.7/KICQ из нового архива. Можно использовать прежнее дерево сборки; в идеале — SDK ревизии 495fea6.
2. Clean → Rebuild, Release | x64. Не определяйте DBAC_NOTINLIST или PMLICQ_ALLOW_LEGACY_CONTACT_API вручную. CMake: legacy OFF.
3. В Output компилятора ищите `PMLICQ contact ABI: old SDK, runtime bridge for #28846` либо `PMLICQ contact ABI: native (module, flags)` (в зависимости от заголовков). Ошибки C1189 из Fix 2 в актуальном коде больше нет.
4. Полностью закройте Miranda, сохраните профиль и предыдущую DLL, установите новую PMLICQ.dll (версия 0.1.0.3). Сохраните PDB этой же сборки. Сначала проверьте на копии профиля: подключение, импорт серверного списка, добавление нового UIN/SN и временного контакта.
5. Если проблема повторяется, приложите DLL/PDB, Crash Report, лог сборки и Netlib log. Не отправляйте профиль или пароли.

## Проверки

- tests/test_contact_api.py: 8 компиляций и запусков с заглушками (старый SDK + #28846, отказ при неизвестном runtime/отсутствии ядра/экспорта, приоритет переходника над legacy opt-in, native и legacy пути во всех вариантах). GCC -Wall -Wextra -Werror.
- tests/test_live_mood.py: 1 запуск, в том числе битые длины.
- tests/identity_test.cpp и tests/avatar_offline_test.cpp: по 4 запуска.

MSVC/Windows DLL и реальный запуск Miranda не проверены в данной среде. Это исходники экспериментального исправления, не подтверждённый бинарный релиз. Старые README и патчи оставлены как история; при расхождениях использовать эту инструкцию.
