# PMLICQ ARS RX FIX7 — регистрация входящих файловых событий в интерфейсе Miranda

Это **тестовое** изменение поверх RX FIX6. Изменён только `KICQ/src/proto.cpp` в четырёх вариантах исходников (0.96.7 и 0.96.8, x86 и x64).

## Изменения

- Для каждой конкретной учётной записи регистрируется `EVENTTYPE_FILE` с флагами `DETF_HISTORY | DETF_MSGWINDOW` через `DbEvent_RegisterType` в `OnModulesLoaded()`.
- Перед `db_event_add` удаляются флаги `DBEF_READ`, `DBEF_SENT` и `DBEF_TEMPORARY`, чтобы входящий запрос оставался непрочитанным событием.
- В Netlib Log выводятся строки `ARS RX FIX7` (результат регистрации типа и флаги).
- Сетевой протокол ARS/OFT2 и рабочая исходящая передача файлов не изменялись.

## Ограничение

Изменения исправляют описание события для Miranda, **но ещё не доказывают**, что TabSRMM и Clist_modern откроют файловое окно при щелчке. На это также влияют настройка уведомлений, обработчик событий файла и доступность `FILE_BLOB`/`FileAllow`. Компиляция и тесты в Windows не выполнены.

## Проверка

1. Сделать резервную копию работающей `PMLICQ.dll` и профиля Miranda.
2. Собрать соответствующий проект в Visual Studio, заменить DLL и перезапустить Miranda.
3. Получить входящий файловый запрос от другого клиента.
4. Проверить значок события у контакта, панель задач и действие по нажатию уведомления.
5. Если диалог не появится, приложить Netlib Log с `ARS RX FIX7` и указать, какой модуль показывает всплывающее уведомление (NewEventNotify/TabSRMM/StdPopup).

**Не публикуйте это как проверенный стабильный релиз до теста.**
