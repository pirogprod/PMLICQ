# PMLICQ — ARS/OFT2 V5: исходящая передача

Это **тестовая версия исходников**, основанная на V4. Входящая ARS-передача,
которая уже подтверждена пользователем как работающая, не изменена.

## Что изменено

1. Только при исходящей ARS-передаче формируется OSCAR channel-2
   rendezvous по документированному порядку TLV для Stage 1:
   000A, 000F, 0002, 0016, 0003 (если известен локальный IPv4),
   0005, 0017, 0010, 2711. Это попытка повысить совместимость
   со старыми принимающими клиентами, а не гарантия доставки.
2. TLV 0003 теперь содержит локальный адрес отправителя, а не
   адрес ARS-прокси. TLV 0002 по-прежнему содержит адрес прокси.
3. Добавлена диагностика ответа ARS READY и этапов передачи OFT2.
   Прямые передачи и приём ARS не переписаны.

## Как проверить

1. Сохрани рабочую DLL V4 и резервную копию профиля.
2. Собери PMLICQ V5 для нужной версии Miranda и разрядности.
3. Отправь небольшой `test.txt` из Miranda в другой клиент
   с рабочим ARS Proxy.
4. В Netlib-логе найди `ARS TX V5`:
   - `waiting for relay READY` — приглашение отправлено, ждём пару.
   - `last response=0` — прокси не прислал READY или тайм-аут сокета.
   - `last response=1` — прокси вернул команду ошибки.
   - `OFT2 result=failure stage=1` — не отправлен PROMPT.
   - `stage=2` — не получен OFT2 ACK от принимающего клиента.
   - `stage=3` — ошибка отправки содержимого файла.
   - `stage=4` — файл передан, но не пришёл DONE.
   - `stage=5` — подтверждено завершение.

## Ограничения

Сборка Windows DLL и настоящая отправка через Mandarin ARS не проверялись.
Подтверждённая работоспособность входящей передачи — результат теста
пользователя для V4, а не нового теста V5.

Изменены исходники только:
- KICQ/src/proto.cpp
- KICQ/src/ars_proxy.h
- KICQ/src/oft2_rendezvous.h
- KICQ/src/oft2_socket_transfer.h
в четырёх ветках 0.96.7/0.96.8 x64/x86.

Документация протокола: «On Sending Files via OSCAR», Stage 1 Proxy Server.
https://www.cs.cmu.edu/~jhclark/aim/On%20Sending%20Files%20via%20OSCAR.pdf
