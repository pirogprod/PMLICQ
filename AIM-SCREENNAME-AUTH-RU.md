# PMLICQ: AIM Screen Name + ICQ UIN — экспериментальные исходники

Обновлены все четыре варианта Miranda NG 0.96.7 / 0.96.8 (normal и Windows XP x86). Поле учётной записи UIN/SN принимает числовой UIN или Screen Name. Старый DWORD UIN сохранён для числовых учётных записей; для строковых добавлены LoginId и ScreenName. Уникальный идентификатор Miranda теперь ScreenName (для прежних UIN создаётся строковое значение при загрузке). Это может затронуть сторонние плагины, ожидающие уникальный ID типа DWORD. Используйте резервную копию профиля; для AIM рекомендуется отдельная учётная запись. Идентификаторы AIM сравниваются без ASCII-регистра и пробелов.

Добавление по точному SN (локальный результат, не проверка существования на сервере), SSI, присутствие, текстовые сообщения OSCAR channel 1, уведомления набора и доставки, запрос/ответ авторизации. При входе по SN стандартный пресет выбирает AIM 5.x; вручную выбранные другие пресеты сохраняются. Используется прежний XOR login (до 8 символов пароля); требуется совместимый OSCAR-сервер, MD5/современная авторизация не реализована. Профильный поиск UIN сохранён для ICQ. AIM-файлы, аватары, X-status и ICQ meta для SN не реализованы; их числовые пути сохранены. Меню Request authorization again доступно ожидающему авторизации контакту при подключении, входящие запросы передаются в Proto_AuthRecv как EVENTTYPE_AUTHREQUEST. Реальное уведомление зависит от ядра Miranda, настроек и сервера.

Сборка: используйте штатные инструкции README.md, BUILD-WINDOWS-XP.md и README-PORT-0968-RU.txt соответствующей версии. Новые исходники встроены в существующие .cpp, отдельный oscar_identity.h не требует отдельного объекта компиляции. Windows DLL не собрана: MSVC/Windows SDK и тестовый OSCAR-сервер отсутствовали. Это не проверенный релиз.

Проверки Linux: g++ -std=c++17 -I<ветка>/KICQ/src tests/identity_test.cpp -o identity_test (все четыре ветки, PASS); g++ -std=c++17 test_avatar_ssi.cpp -o test_avatar_ssi (PASS). После сборки вручную: вход старым UIN; вход отдельным SN; добавление UIN и SN с разным регистром/пробелами; сообщения в обе стороны, онлайн/оффлайн, набор, доставка; входящий auth request, подтверждение/отказ, повторный запрос; повторный вход и сохранение roster; регрессии аватаров, файлов, X-status, прокси. Проверить работу с ICQ и AIM аккаунтами на одном совместимом сервере.
