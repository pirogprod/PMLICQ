# PMLICQ — ARS ALLOCATE V6 (исходящая передача)

## Основание: Netlib-лог пользователя

В 03:51:44 исходящая ARS-передача достигла TCP прокси, но до 03:51:49 не получила `ALLOCATE_OK`; затем активировала прямой OFT2 с приватным адресом `172.19.0.1` и не смогла дождаться подключения получателя. Следовательно, конкретная неудача произошла **до** ARS READY / OFT2 PROMPT. Правка кодирования OFT2-пакетов здесь не устранит причину.

## Изменения V6

- Команда ARS `0x0001` (ошибка) больше не отбрасывается чтением кадров. `handshakeAllocate` сообщает в логах ответ `reply` и 16-битный `proxyError`.
- На настроенном TCP-порту `5191`, если ALLOCATE не принят и приглашение ещё не отправлено, выполняется однократная попытка на классическом ARS TCP-порту `5190` **того же адреса прокси**. При успехе этот порт также используется при дальнейшем повторном подключении в рамках исходящей передачи.
- При успехе ALLOCATE исходящая отправка продолжает старую цепочку: OSCAR приглашение → READY → OFT2. Она не переписана.
- По истечении 8 секунд на ALLOCATE фиксируется отсутствие ответа; этот тайм-аут относится только к ALLOCATE и не меняет время передачи данных.
- Для любого другого явно настроенного порта автоматического перебора портов **нет**.

## Какие исходники затронуты

Для всех комбинаций 0.96.7 / 0.96.8 и x64 / x86 XP изменены **только**:
- `KICQ/src/ars_proxy.h`
- `KICQ/src/proto.cpp`

Файлы `server.cpp`, обработчики входящего ARS, объявления X-статусов, ресурсы и клиентские fingerprint-каталоги не менялись.

## Диагностика

Искать в Netlib-логе:

```
ARS TX V6: TCP connected to configured relay port ...
ARS TX V6: ALLOCATE not accepted ... (reply=... proxyError=...)
ARS TX V6: retry ALLOCATE on classic ARS TCP port 5190
ARS TX V6: classic port did not allocate (reply=... proxyError=...)
ARS DIAG3: ALLOCATE_OK ...
ARS TX V5: waiting for relay READY ...
```

Значения `proxyError=13` / `0x000D` обозначают bad request согласно описанию классического ARS. Если `reply=0`, это не означает отказ протокола: ответ мог не поступить за время ожидания.

## Установка и ограничения

1. Сделать резервную копию рабочей `PMLICQ.dll` и профиля.
2. Собрать нужную ветку через Visual Studio / Miranda SDK для **своей версии Miranda**.
3. Заменять DLL только при закрытой Miranda NG.
4. Убедиться, что ARS Proxy в настройках указан как *имя хоста* (без `http://`, без `:порт`), а порт прописан в отдельном поле.
5. Проверить отправку маленького тестового файла; сравнить строки выше.

**Ограничение:** без соединения с реальным Mandarin ARS нельзя подтвердить, что на 5190 находится совместимый ARS. Эта версия исправляет обработку ошибок и проверяет обоснованную гипотезу о неверном старом порте; не гарантирует полноценную передачу.

Входящая ARS-передача ранее была подтверждена пользователем как рабочая; её код не меняли.
