# История изменений PMLICQ

## 2026-11-08 — ARS Proxy / OFT2, RX FIX9 (TEST)

### Файловый транспорт

- Добавлена тестовая передача одного файла через **OSCAR Rendezvous + ARS-прокси + OFT2**, на базе существующей реализации PMLICQ и с учётом обновления KICQ от Symnok.
- Добавлены параметры ARS-сервера и порта, попытки переподключения/переадресации, обработка отмены сокета и диагностические записи `ARS`.
- Усилена безопасность Win32/x86: `_beginthreadex`, защита состояния сокетов, ограничения ожидания, проверки имени принимаемого файла.

### Исправления приёма файлов

- **RX DIAG4:** диагностический вывод входящего OSCAR ICBM/Rendezvous до фильтра `CAP_FILE`.
- **RX FIX5:** указание протокольного модуля `DBEVENTINFO.szModule` для события входящего файла; исследование `SQLITE_CONSTRAINT`.
- **RX FIX6:** указание типа `EVENTTYPE_FILE` вместо обычного сообщения.
- **RX FIX7:** исследование регистрации файлового типа события и отображения уведомлений.
- **RX FIX8:** переход на стандартный маршрут `CSuper::RecvFile()` вместо прямой записи через `db_event_add`; исключена некорректная маршрутизация в TabSRMM.
- **RX FIX9:** в `IncomingProgress()` для `ACKRESULT_DATA` передаются папка `szWorkingDir`, полный путь `szCurrentFile` и Unicode-флаг до финального `ACKRESULT_SUCCESS`, чтобы кнопка «Открыть файл» использовала полученный файл, а не папку по умолчанию.

### Статус проверки

Пользователь сообщил о работающей отправке из PMLICQ и последующем получении файла в PMLICQ. Открытие принятого файла после FIX9, сборка всех четырёх целевых вариантов и устойчивость на разных серверах **пока не подтверждены**. Релиз маркируется **TEST / BETA**.

### Не менялось намеренно

Контакты, группы, сообщения, авторизация, X-статусы, BART-аватары и настройки, не относящиеся к передаче файлов.

## 2026-11-21 — входящий Client ID, ExtraIcons, x86/x64, перенос на 0.96.8 (SOURCE)

- Дополнен определитель входящих OSCAR Client ID: отдельные правила по подтверждённым capability fingerprints для ICQ 6 (14 GUID), ICQ 5.1 (14 GUID), QIP 2012 (7 GUID), с приоритетом над более общими сигнатурами. Исправлено ложное определение ICQ 5.1 как Jimm.
- Добавлены значки клиентов через отдельный ExtraIcon `PMLICQ Client`; PNG пользовательского набора преобразованы в ICO и включены в ресурсы DLL-проекта.
- x86: сохранены исправления обращения к ExtraIcons и обновления контактов; ветка Win32 использует параметры проекта для `v141_xp` и Windows XP.
- x64: уменьшено число повторных записей и перерисовок контактов при неизменном присутствии и Client ID. Пользователь сообщил об улучшении быстродействия.
- Подготовлен порт актуальных исходников на Miranda NG 0.96.8, сохраняя отдельные деревья x64 и x86.
- Рабочая отправка `Miranda NG PMLICQ 0.96.7.0`, X-статусы и текущий транспорт не изменялись намеренно при последующих точечных исправлениях.

**Ограничения:** это исходники без готовых DLL; полная сборка и тестирование на всех целевых системах, включая XP, не подтверждены. Для клиентских иконок требуется проверка прав перед публичным выпуском.

## Обновление 22.11.2026 — значки клиентов вынесены в Fingerprint

- **PMLICQ** остаётся отдельным протокольным модулем и продолжает распознавать клиентское ПО контактов по входящим capabilities, сохраняя результат в поле `MirVer`. Распознавание ICQ 5.1, ICQ 6, QIP 2012, QIP 2005, Jimm и прочих известных клиентов сохранено; ранее исправленные входящие сигнатуры не изменялись при переносе значков.
- Из веток PMLICQ **0.96.7 и 0.96.8 (x64 и x86/Windows XP)** удалены только собственные клиентские ExtraIcons (`PMLICQ_Client`) и их ресурсные иконки. Отдельные X-статусы `PMLICQ_XStatus` не удалялись.
- За отображение значков клиента теперь отвечает **внешний Fingerprint**, используя `MirVer`, `fingerprint.json` и набор пользовательских ICO. Для QIP 2005a и `QIP ver. 2005a`, ICQ 5.1, ICQ 6, QIP 2012 и остальных клиентов разработан отдельный набор правил сопоставления.
- Добавлена маска `*magent*` для обозначений Mail.Ru Agent (`client="magent" version="6.3" build="8065"` и других версий/вариантов написания); значок — `cli_mailru.ico`. Это правило применяется в конфигурации **Fingerprint**, а не в исходниках PMLICQ.
- В отдельном пакете Fingerprint подготовлены расширенные `Fp_icons.dll` для x64 и x86 и дополнительные ICO. **Эти DLL не являются зависимостями PMLICQ и в настоящий репозиторий исходников не включаются.** Подробности: `FINGERPRINT-INTEGRATION-RU.md`.
- Сохранены прежние особенности стабильных веток: оптимизация обновления списка контактов для x64 и настройки сборки x86 с поддержкой XP на уровне проекта. Сетевой протокол, исходящая идентификация `Miranda NG PMLICQ`, сообщения, файлы и X-статусы в этом обновлении не изменялись.

**Ограничения проверки:** архив с исходниками сопоставлен с предыдущими версиями; запуск PMLICQ и отображение клиентских иконок в реальной Miranda NG на всех платформах не проводились. Пользовательские правила Fingerprint следует устанавливать отдельно, сохраняя резервную копию своего `fingerprint.json`.
