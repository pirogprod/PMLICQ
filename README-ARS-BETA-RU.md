# PMLICQ — ARS file proxy (тестовая ветка)

Варианты: **x86 Windows XP SP3** и **x64**, Miranda NG **0.96.7 / 0.96.8**.

Обновления ограничены подсистемой передачи файлов: транспорт ARS (протокол `0x044A`),
приглашения OSCAR/Rendezvous (TLV `0x10`), OFT2, элементы настройки ARS proxy/port,
отмена ожидающих сокетов, защита пути входящего файла и потоков x86.

По умолчанию: `ars.mandarin.im`, порт `5191`. Настройка доступна при создании
учётной записи и в параметрах подключения. Если значение адреса прокси пустое
или порт равен нулю, сохраняется исходный прямой OFT2.

**Ограничения этой интеграции:** поддерживается только **один файл за передачу**.
Многофайловые сессии и переадресация ARS при невозможности соединиться с прокси
ещё не портированы полностью (есть попытка запасного адреса прокси при получении).
Это самостоятельная интеграция ARS-механизма по формату Symnok, но **не полная
побайтовая копия его реализации**. Запуск подключения и отправки через серверы
Open OSCAR Server / iserverd здесь не проверен.

**Стабильность x86:** `_beginthreadex` для потоков передачи, выделенный сокет
внутри потока, `shutdown` по отмене/выходу, ограниченные ожидания, проверка входящих
имён и запрет перезаписи существующих файлов. Это снижает ряд известных рисков,
но **не гарантирует отсутствие DEP-вылетов**. Компиляция в Visual Studio и
сетевые интеграционные тесты в этой среде недоступны.

## Тестирование

1. Сделайте резервную копию работающей `PMLICQ.dll` и portable-профиля.
2. Соберите выбранный проект с **соответствующим SDK Miranda NG** в VS 2019.
3. Для Windows XP используйте `Release | Win32`, toolset `v141_xp` и `/Od`.
4. Проверьте отправку одного малого файла в QIP / другой OSCAR-клиент и обратную
   передачу, затем отмену во время соединения и повторное подключение.
5. Сохраните Netlib Log и CrashDumper/PDB при неудаче. Не публикуйте как
   стабильный релиз до тестов обеих архитектур.
