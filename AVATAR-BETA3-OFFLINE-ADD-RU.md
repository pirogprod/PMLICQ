# PMLICQ V9 — Avatar Beta 3: офлайн-контакты и добавление контакта

Основа: `PMLICQ_V9_AIM_SN_AUTH_SOURCE.zip` (AIM SN + авторизация + Avatar Beta 2). Все четыре ветки: normal/0.96.7, normal/0.96.8, windows-xp-x86/0.96.7 и windows-xp-x86/0.96.8.

## Что изменено

- BUDDY rights (03/02), TLV 0005: сохраняются флаги 0003 и добавляется OFFLINE_BART_SUPPORTED (0004). Сервер может присылать аватарки для офлайн-контактов.
- После входа планируется запрос LOCATE 02/15 (флаг 00000004, имя с длиной) для каждого локального контакта данного аккаунта, независимо от статуса. Обрабатывается ответ 02/06; прежние 01/0F и 03/0B сохраняются. 03/0C с полным USERINFO также может предоставить аватар. Статус офлайн не превращается в онлайн из-за стандартного BART-уведомления.
- Новое добавление ставится в приоритетную очередь; после результата SSI 13/0E отправляется BuddyAdd (03/04) и повторная проверка метаданных для UIN и SN. Серверные добавления также обрабатываются. Не более 4 запросов LOCATE за один секундный интервал, без постоянного опроса. При отсутствии ответа повторный запрос возможен при переподключении или добавлении.
- Декодирование метаданных и поиск контакта по строковому идентификатору поддерживают AIM SN; числовые UIN сохраняются. Прежний BART 10/06 и 10/07, загрузка собственной аватарки и её SSI-публикация не переписаны.
- Проверяется наличие непустого файла кэша. Если файл отсутствует, запрашивается последний известный хеш; существующий актуальный кэш не скачивается заново. Для старых XP-профилей поддерживается прежний BartAvatarHash. Запоздалый ответ для устаревшего хеша не заменяет актуальную картинку. При новом входе очищается очередь предыдущей BART-сессии и останавливается прежний worker.
- При успешной загрузке сохраняется ContactPhoto/File и отправляется прежний ACKTYPE_AVATAR для конкретного контакта.

## Ограничения

BART-запрос скачивания требует реальный идентификатор аватара (тип/хеш); клиент не может вычислить неизвестный хеш по UIN/SN. Если сервер не отдаёт метаданные для офлайн-пользователя, изображение без ранее известного хеша получить невозможно. AIM-аватары зависят от поддержки SN сервером. Код сервера не входит в этот патч. Изменения не затрагивают OFT2/ARS, X-status, идентификацию клиентов, авторизацию, вход и настройки. Общие сетевые обработчики изменены только в местах, связанных с аватарами и подпиской.

Справка OSCAR: https://wiki.nina.chat/wiki/Protocols/OSCAR/SNAC/BUDDY_RIGHTS_QUERY ; https://wiki.nina.chat/wiki/Protocols/OSCAR/SNAC/LOCATE_USER_INFO_QUERY2 ; https://wiki.nina.chat/wiki/Protocols/OSCAR/SNAC_03_0B .

## Проверки

`tests/avatar_offline_test.cpp` — автономный C++17 тест, собран и выполнен с заголовками каждой из четырёх веток. Проверяет запрос LOCATE, числовые и строковые имена, метаданные офлайн, обычный онлайн-статус, отдельный X-status, лишние и усечённые TLV, формат запроса/ответа BART. Это не интеграционный тест Miranda.

Windows DLL не компилировались: в окружении нет MSVC/Windows SDK/Miranda SDK. Реальная загрузка на сервере не проверена.

## Ручная проверка

1. Скопировать DLL и профиль Miranda. Войти аккаунтом, имеющим онлайн- и офлайн-контакты с аватарками. Дождаться загрузки очереди; проверить, что статус офлайн сохранён.
2. Добавить офлайн UIN с известным аватаром на сервере; проверить появление картинки без переподключения. Повторить для онлайн UIN и AIM SN, если сервер поддерживает AIM/BART.
3. Переподключиться; проверить отсутствующий файл кэша на тестовом профиле и смену аватарки контакта онлайн (регрессия Beta 2).
4. В Netlib-логе искать `BART: requested avatar metadata`, `BART: queued image request`, `BART: cached and announced`. Если есть LOCATE, но нет метаданных/запроса картинки, проверить ответы 02/06, 03/0B или 03/0C от сервера, прежде чем менять серверную часть.
