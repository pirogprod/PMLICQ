# PMLICQ V7 — отправка больших файлов через ARS и настройка прямого OFT2

База: PMLICQ ARS ALLOCATE V6 (входящий и исходящий ARS уже работают для небольших файлов).
Версии: Miranda NG 0.96.7 / 0.96.8, x64 и x86 (включая ветку XP).

## Что изменено

1. Отправка файла блоками 64 КиБ вместо 32 КиБ. Получение файла и его обработчики не менялись.
2. Уведомления о прогрессе Miranda ограничены по частоте (250 мс или 1 МиБ), но первый и последний прогресс не теряются. Это устраняет тысячи лишних синхронных UI-обновлений на больших файлах.
3. Только в отправляющем ARS и прямом OFT2 увеличен размер TCP SO_SNDBUF до 256 КиБ.
4. Добавлен отчёт о результате с номером этапа, количеством отправленных байтов, длительностью и WinSock-кодом.
5. Для прямого OFT2 добавлена необязательная настройка публичного IPv4 и фиксированного локального TCP-порта. Настройки по умолчанию сохранены.
6. Входящие ARS-обработчики, приглашения, OSCAR Client IDs, Fingerprint и X-статусы не менялись.

## Как настроить ARS

Оставь рабочие настройки ARS Proxy из V6. **Не изменяй порт прокси ради V7**.
Попробуй файл 6 МиБ и затем 60 МиБ. Если отказ повторится, включи Netlib-лог и найди:

  ARS TX V7: file data progress BYTES/TOTAL bytes
  ARS TX V7: OFT2 result=failure stage=N dataSent=BYTES/TOTAL elapsedMs=MS WSA=CODE

Стадии: 1=PROMPT; 2=ACK; 3=отправка тела; 4=ожидание DONE; 5=успех.
- stage=3 и dataSent меньше размера: соединение оборвалось при отправке; возможны тайм-ауты/ограничения прокси/получателя или ошибка сети.
- stage=4 и dataSent равно размеру: файл отправлен в сокет целиком, но DONE не получен или не принят.
- stage=2: проблему искать в ответе на PROMPT.
Один лишь размер 60 МБ не доказывает ограничение в коде PMLICQ: лимиты сервера могут сохраняться.

## Прямой OFT2 (в обход ARS)

В V6 при прямой передаче рекламировался выбранный IP локального сетевого интерфейса, который иногда равен 172.19.0.1 (Docker/VPN). Такой адрес недоступен внешнему клиенту.

В V7 добавлены необязательные ключи **в модуле своей учётной записи PMLICQ** (через DBEditor++):
- `Oft2ExternalIP` — Unicode/WCHAR, публичный IPv4-адрес, который другой клиент реально может достичь (пример: `203.0.113.10` — только образец, не использовать буквально).
- `Oft2ListenPort` — Word, локальный TCP-порт для входящего прямого OFT2 (например `5195`).

Для работы за NAT также нужно вручную переадресовать TCP-порт на компьютер с Miranda и разрешить этот порт в брандмауэре. Публичный IP сам по себе не открывает порт. Если у интернет-провайдера CGNAT и нет собственного публичного IPv4, прямой входящий OFT2 без внешнего туннеля/прокси работать не сможет.

При пустых настройках поведение V6 сохраняется: выбираются маршрутный локальный IP и случайный свободный TCP-порт. Если IP частный, Netlib выводит `OFT2 DIRECT WARNING`. Новые ключи влияют только на отправку в режиме прямого OFT2/его fallback, не на ARS.

Ограничение: эта версия всё ещё не поддерживает полноценную автоматическую NAT traversal/UPnP и отправку пачки из нескольких файлов одним запросом.

## Проверено / не проверено

- На Linux выполнен сквозной **локальный** OFT2-тест 64 МиБ с живыми сокетами (`socketpair`) и побайтовым сравнением. Стадия FINISHED и полные 67 108 864 байта пройдены.
- Проверены изменения только в файлах `proto.cpp`, `proto.h`, `oft2_transport.h`, `oft2_socket_transfer.h`, `oft2_listener.h` во всех четырёх ветках.
- **Не** проведена Windows-сборка DLL и реальный тест 60 МиБ через Mandarin ARS; нельзя обещать устранение лимита сервера или гарантировать, что это окончательное исправление. Перед заменой DLL сохранить рабочую V6 и резервную копию профиля.

Архив содержит `tests/ft_v7/test_oft2_64mb.cpp` — переносимый тест сетевого этапа для Linux, а не полноценный эмулятор Mandarin ARS.
