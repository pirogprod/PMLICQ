# PMLICQ ARS RX FIX8 — штатные уведомления о входящих файлах

## Причина
В FIX5–FIX7 переопределение `CKicqProto::RecvFile` самостоятельно сохраняло
событие через `db_event_add`. Это обходило стандартный код Miranda NG,
который добавляет `CLISTEVENT` со службой `SRFile/RecvFile` и открывает окно
приёма файла. Дополнительная регистрация EVENTTYPE_FILE с DETF_MSGWINDOW
направляла событие в TabSRMM.

## Изменение
Только в четырёх `KICQ/src/proto.cpp`:
- Убрана регистрация `EVENTTYPE_FILE` с флагом `DETF_MSGWINDOW`.
- `CKicqProto::RecvFile` вызывает `CSuper::RecvFile`, то есть штатный
  `PROTO_INTERFACE::RecvFile` / `Proto_RecvFile` Miranda NG.
- Событие остаётся входящим и непрочитанным, `blob.getUserInfo()` содержит
  указатель на входящую сессию, используемый `FileAllow`/`FileDeny`.
- Код отправки файла, ARS/OFT2 и других функций не менялся.

## Проверка на Windows
1. Сохранить старую DLL и профиль Miranda.
2. Пересобрать Release Win32 (XP v141_xp /Od) или x64 для 0.96.7/0.96.8.
3. Перезапустить Miranda, отправить один файл с другого клиента.
4. Проверить иконку событий Clist_modern, мигание и диалог по нажатию.
5. Нажать «Принять» и проверить реальное получение файла; затем «Отклонить».
6. При сбое приложить Netlib Log с `ARS RX FIX8` и `ARS DIAG3`.

**Статус:** исходники тестовые. DLL не компилировалась и не испытывалась
на Windows в этой среде. Эта правка исправляет маршрут уведомления,
но не гарантирует успешную передачу данных через ARS.
